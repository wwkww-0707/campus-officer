# 选课规划 Skill

## 适用场景

用户希望了解可选课程、检测时间冲突、获得课程组合推荐，或需要形成一份可留档的选课清单。

## 执行流程（必须按序，不得跳步）

### 第 1 步：盘点已选课程

调用 `get_my_enrollments` 拿到学生当前已选课程与具体时段。

**为什么必须先做**：冲突检测是相对于"已选 + 候选"的联合判定。不知道已选课程就报"无冲突"是错误结论。

### 第 2 步：查询候选课程

调用 `list_courses`，按用户提到的学院、类别、学分区间过滤。用户没说类别时默认查"选修"。

同时向用户确认（或从话里推断）以下参数：
- 目标门数（默认 3 门）
- 学分上限（默认 20 学分）
- 需要避开的星期（若用户说"避开周三下午"）
- 偏好方向（如"想学 AI""偏工程"）

### 第 3 步：做确定性冲突检测

调用 `check_schedule_conflict` 传入候选课程 id。

**关键**：冲突结论以工具返回为准，**不要自己目测时间**。工具用闭区间 `[start_period, end_period]` 求交判定，与人工目测口径一致且可复现。

### 第 4 步：求解课程组合

若用户要"帮我挑 N 门"，调用课程组合求解子代理（`core/subagents.py` 的 `course_combination_agent`），
它按先修、无冲突、学分上限、容量四重约束做回溯搜索。

拿到组合后，**必须把求解过程讲清楚**：先修是否满足、冲突如何排除、为什么没选某门。

### 第 5 步：确认后写入

推荐组合只是建议。**只有在用户明确确认后**才调用 `enroll_course` 提交。

提交失败时，把后端返回的具体原因（满员 / 冲突 / 超学分）如实转述，不要替换成模糊表述。

### 第 6 步：产出选课清单

调用 `write_artifact` 生成 Markdown 清单，用 `templates/course_plan_template.md` 的结构。

## 输出要求

1. 表格列出课程代码、名称、学分、时段、余量；
2. 写明总学分与上限、剩余可选学分；
3. 明确标注"冲突检测结论"及判定依据；
4. 列出**未选中课程及原因**（满员 / 先修未满足 / 冲突 / 超出上限）——这部分常被忽略，但对用户决策最有价值；
5. 结尾附合规声明："本清单基于演示用虚构数据生成，仅供选课参考，实际以教务系统为准。"

## 禁止事项

- 禁止凭记忆编造课程代码、学分、上课时间——必须来自 `list_courses`；
- 禁止在用户未确认前调用 `enroll_course`；
- 禁止把"满员课程"推荐给用户而不加说明。
