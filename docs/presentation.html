01 · 问题与用户

学生办一件事，要自己拼五个系统问题不在"查不到"，而在"拼不起来"

1信息散落

课程目录在教务系统、通知在官网、校规在制度汇编、奖助条件在学工处文件、学分进度在个人页 —— 一次选课要开五个标签页自己对照。

2条款有"保质期"

校内制度都有文号与生效期。旧版《奖助学金办法》还在网上流传， 学生按作废条款准备材料，白跑一趟。

3多约束同时满足

「避开周三下午、不超过 20 学分、别和已选课冲突、优先值得上的」—— 四个约束一起满足，人脑穷举容易漏，跨专业选课时更明显。

用户　在校本科生（本案为大数据专业大二学生），场景集中在 选课周与奖助申报期两个时间窗。
一句话价值　把"我自己去查、去比、去填表"变成 "说一句需求 → 它规划步骤 → 调真实工具 → 交一份能直接用的文件"。

为什么不做一个"更强的搜索框"

搜索只解决"找得到"，解决不了"办得成"。本项目要跑通的是事务链：

  • 选课要求解组合（约束满足），不是返回一堆课名
  • 资格要逐项比对门槛并给依据，不是给个链接
  • 政策要核验时效并标文号，不是复述一段话

这也是选路径 A 而不是路径 B 的原因：核心价值在"工具 + 编排"，不在检索。

手写 LangGraph 状态图core/graph.py:103-148

core/graph.py_build()
def _build(self):
    graph = StateGraph(CampusState)

    graph.add_node("planner", self._node_plan)   # 拆步骤
    graph.add_node("agent",   self._node_agent)  # 调模型
    graph.add_node("tools",   self._node_tools)  # 执行工具
    graph.add_node("reflect", self._node_reflect)# 合规校验
    graph.add_node("rule",    self._node_rule)   # 降级

    graph.add_edge(START, "planner")
    graph.add_conditional_edges(
        "planner", self._route_after_plan,
        {"agent": "agent", "rule": "rule"})
    graph.add_conditional_edges(
        "agent", self._route_after_agent,
        {"tools": "tools", "reflect": "reflect",
         "rule": "rule"})
    graph.add_edge("tools", "agent")   # 结果回给模型
    graph.add_edge("reflect", END)
    graph.add_edge("rule", END)
    return graph.compile()
core/graph.py条件路由
def _route_after_agent(state):
    if state.get("model_failed"):
        return "rule"      # 模型中途挂
    if state.get("force_reflect"):
        return "reflect"   # 轮次到顶
    resp = state.get("response")
    if resp and resp.tool_calls:
        return "tools"     # 继续调工具
    return "reflect"
为什么不用 create_react_agent：预构建封装把工具循环藏成黑盒， 拿不到中间事件，也插不进二次确认与降级分支。
  • messages / events 用 operator.add 归约：节点只返回增量，框架负责累加
  • 三个出口：还有工具→tools；说完话→reflect；模型失败→rule
  • 编译成真实图后，节点可单独测试，不依赖界面

冲突检测：交给代码，不交给模型backend/schedule.py:19-66

backend/schedule.py闭区间求交
def slots_overlap(a: Timeslot, b: Timeslot) -> bool:
    """同一天且节次闭区间有交集即为冲突。"""
    if a.weekday != b.weekday:
        return False
    return (a.start_period <= b.end_period
            and b.start_period <= a.end_period)
    # 1-2 节 与 2-3 节 共享第 2 节 → 算冲突


def detect_conflicts(courses):
    """两两检测，combinations 保证每对只比一次"""
    return [p for ca, cb in combinations(courses, 2)
            if (p := find_conflict_pair(ca, cb))]
最容易讲错的地方：边界相接　若写成开区间（<）， 1-2 节与 2-3 节会被判成"不冲突"，学生按此选课就会出现同一天第 2 节撞车。 必须用闭区间才能覆盖共享节次。
  • 为什么不让模型判：模型对边界相接极易漏判，且同一问题两次可能不同答案 —— 这是确定性规则，必须可复现
  • 复杂度 O(n² × slots²)：12 门课不足 100 次比较，教学规模完全够用
  • 结果可解释：返回具体冲突片段（周几、第几节、教室），界面直接展示
  • 被工具（check_schedule_conflict）与子代理（回溯求解）共用
测试覆盖　tests/test_schedule.py 断言了区间相接、包含、不相交、 多时段、三课两两冲突等边界情况。

知识库：先降权，再排序core/knowledge.py:38 · 163-205

core/knowledge.pyBM25 + 失效降权
EXPIRED_PENALTY = 0.25   # 已失效条款的降权系数

def search(self, query, top_k=5, category=None):
    q = tokenize(query)          # jieba 分词
    scored = [(self._bm25(q, d), d)
              for d in self.docs]

    weighted = []
    for score, doc in scored:
        note = ""
        if doc.clause.is_expired:      # ① 先降权
            score *= EXPIRED_PENALTY
            note = f"已于 {doc.clause.effective_to} 失效"
        weighted.append((score, doc, note))

    weighted.sort(key=lambda x: x[0],
                  reverse=True)      # ② 再排序
    return [...][:top_k]
踩过的坑　最初写成"先排序取 top_k，再对结果降权"， 失效条款仍排第一 —— 降权发生在截断之后，等于没降。 改成先降权再排序才真正沉底。
  • 条款元数据：文号、生效日、失效日、来源 —— 回答可溯源
  • 三类标注：真实条款 / 校内演示样例 / 已失效，界面分别提示
  • 18 条条款覆盖奖助、学籍、选课、四六级、考研、宿舍等
  • 库里故意保留一条已失效旧办法，用来演示降权机制
合规底线　任何回答都附「以学校官方最新文件为准」， 不把检索结果包装成官方结论。

10 · 思政与合规

数据从哪来、边界在哪也是评分表"问答与规范"的观察点

选题正当性

服务校园治理中的正当需求：信息可核验、办事少跑腿。 不做代写、不做监控、不编造政策结论。

数据来源可核验

  • 政策条款：每条带文号 + 生效期 + 来源，失效条款降权并明示
  • 校园通知：同步自学校官网，保留原文链接可点回
  • 学生档案：全部虚构样例，界面注明"演示用"

隐私最小化

只保留学号、专业、GPA、困难认定等办事必需字段； 不采集身份证、手机号、住址；数据存本地 SQLite，不上传。

权限隔离：Agent 只能写 outputs/

core/artifacts.py路径守卫
if ".." in raw or "/" in raw \
   or "\\" in raw or ":" in raw:
    raise PermissionError("仅允许写入
        outputs/ 内的纯文件名")

显式拒绝而不是静默改写 —— 越权意图必须被拦下并告知调用方。 选课等写操作另有二次确认：模型只能提出，执行权在用户。

使用边界　资格判定只做初筛，最终以学校认定为准； 政策解读标注"以官方最新文件为准"；不替代辅导员与教务处的正式结论。
密钥管理　.env 已进 .gitignore，仓库只提交 .env.example；提交前做过全仓扫描，无 Key 泄漏。
